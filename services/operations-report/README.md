# Операційний звіт (operations-report)

## 1. Загальна інформація

**Назва проєкту:** Операційний звіт (operations-report)

**Команда:** №8 (team-8)

**Мета проєкту:** Сформувати підсумковий стан платформи на основі агрегованих показників її роботи. Сервіс аналізує кількість пристроїв, критичних сигналів, перевантажених вузлів та інцидентів, обчислює відсоток активних пристроїв і загальний показник працездатності платформи (Health Score).

На основі отриманих даних сервіс визначає поточний статус платформи:
- `STABLE` — стабільний стан;
- `DEGRADED` — погіршений стан;
- `CRITICAL` — критичний стан.

Також сервіс формує перелік основних операційних ризиків.

## 4. Вхідні дані

Сервіс використовує структуру `OperationsSummary`, яка містить агреговані показники стану платформи.

| Поле | Тип даних | Опис |
|---|---|---|
| `devices` | `int` | Загальна кількість пристроїв у системі |
| `online` | `int` | Кількість пристроїв, що перебувають онлайн |
| `criticalSignals` | `int` | Кількість критичних сигналів |
| `overloadedNodes` | `int` | Кількість перевантажених вузлів |
| `openIncidents` | `int` | Кількість відкритих інцидентів |
| `criticalIncidents` | `int` | Кількість критичних інцидентів |
| `availability` | `double` | Доступність платформи у відсотках |
| `recovered` | `bool` | Ознака відновлення системи (1 — так, 0 — ні) |

Дані вводяться користувачем через консоль за допомогою функції `readSummary()`.

**Приклад введення:**

```text
Enter number of devices: 10
Enter number of online devices: 9
Enter critical signals: 0
Enter overloaded nodes: 0
Enter open incidents: 0
Enter critical incidents: 0
Enter availability (%): 99.5
Was system recovered? (1 - yes, 0 - no): 1
```

## 5. Вихідні дані

Після успішної перевірки вхідних даних програма формує операційний звіт, який містить:

- загальну кількість пристроїв;
- кількість пристроїв онлайн;
- відсоток активних пристроїв;
- показник доступності платформи;
- Health Score від 0 до 100;
- поточний статус платформи;
- перелік основних операційних ризиків.

**Приклад вихідного звіту:**

```text
Devices: 10
Online devices: 9
Online percentage: 90%
Availability: 99.5%
Health score: 95
Status: STABLE
Risks:
- 1 devices are offline
```

Якщо під час перевірки виявлено некоректні дані, програма виводить повідомлення:

```text
Invalid data!
```

## 6. Правила валідації та обчислення показників

Перед формуванням звіту програма перевіряє коректність вхідних даних за допомогою функції `validateSummary()`.

### 6.1. Правила валідації

Вхідні дані вважаються коректними, якщо виконуються всі умови:

1. Кількість пристроїв (`devices`) не може бути від'ємною.
2. Кількість пристроїв онлайн (`online`) не може бути від'ємною.
3. Кількість пристроїв онлайн не може перевищувати загальну кількість пристроїв:
   
   `online <= devices`

4. Кількість критичних сигналів (`criticalSignals`) не може бути від'ємною.
5. Кількість перевантажених вузлів (`overloadedNodes`) не може бути від'ємною.
6. Кількість відкритих інцидентів (`openIncidents`) не може бути від'ємною.
7. Кількість критичних інцидентів (`criticalIncidents`) не може бути від'ємною.
8. Доступність платформи (`availability`) повинна перебувати в межах від 0 до 100 включно.

Якщо хоча б одна умова порушена, програма відхиляє введені дані та не формує звіт.

### 6.2. Розрахунок відсотка активних пристроїв

Для визначення відсотка пристроїв, які перебувають онлайн, використовується формула:

```text
onlinePercent = (online / devices) * 100
```

Якщо загальна кількість пристроїв дорівнює нулю, функція повертає `0`, щоб уникнути ділення на нуль.

Розрахунок виконується функцією `calculateOnlinePercent()`.

### 6.3. Розрахунок Health Score

Health Score — це числовий показник загального стану платформи в діапазоні від 0 до 100.

Спочатку визначається кількість пристроїв, які перебувають офлайн:

```text
offlineDevices = devices - online
```

Далі обчислюється показник здоров'я системи за формулою:

```text
score = 100
        - offlineDevices * 5
        - criticalSignals * 5
        - overloadedNodes * 7
        - openIncidents * 2
        - criticalIncidents * 10
```

Результат обмежується діапазоном від 0 до 100:

- якщо результат менший за 0, встановлюється 0;
- якщо результат більший за 100, встановлюється 100.

Розрахунок виконується функцією `calculateHealthScore()`.

### 6.4. Шкала статусів платформи

Після обчислення Health Score програма визначає статус платформи за такими правилами:

| Health Score | Статус | Значення |
|---|---|---|
| 80–100 | `STABLE` | Платформа працює стабільно |
| 50–79 | `DEGRADED` | Працездатність платформи погіршена |
| 0–49 | `CRITICAL` | Критичний стан платформи |

Визначення статусу виконується функцією `classifyPlatform()`.

### 6.5. Визначення основних ризиків

Функція `printRisks()` аналізує показники та виводить ризики, якщо відповідні значення більші за нуль:

- наявність пристроїв офлайн;
- виявлення критичних сигналів;
- наявність перевантажених вузлів;
- наявність відкритих інцидентів;
- наявність критичних інцидентів.

## 8. Збірка та запуск проєкту

### 8.1. Необхідне програмне забезпечення

Для компіляції та запуску потрібні:

- компілятор C++ із підтримкою стандарту C++17;
- `g++` (наприклад, GCC);
- термінал або командний рядок.

### 8.2. Перехід до каталогу проєкту

Відкрийте термінал у кореневому каталозі `operations-report`.

Якщо ви перебуваєте в батьківському каталозі, виконайте:

```bash
cd operations-report
```

### 9.3. Компіляція

Для збірки програми виконайте команду:

```bash
g++ -std=c++17 -Wall -Wextra -pedantic src/main.cpp -o app
```

Пояснення параметрів:

- `-std=c++17` — використання стандарту C++17;
- `-Wall` — увімкнення основних попереджень компілятора;
- `-Wextra` — увімкнення додаткових попереджень;
- `-pedantic` — перевірка відповідності стандарту C++;
- `src/main.cpp` — шлях до вихідного файлу;
- `-o app` — назва виконуваного файлу.

Якщо компіляція пройшла успішно, у кореневому каталозі буде створено виконуваний файл `app`.

### 9.4. Запуск програми

Для запуску виконайте:

```bash
./app
```

Після запуску з'явиться меню:

```text
===== =====
1. Create report
0. Exit
Choose:
```

Введіть `1`, щоб створити операційний звіт, або `0`, щоб завершити роботу програми.

### 9.5. Перевірка роботи програми

Для перевірки введіть контрольні дані:

```text
Choose: 1
Enter number of devices: 10
Enter number of online devices: 9
Enter critical signals: 0
Enter overloaded nodes: 0
Enter open incidents: 0
Enter critical incidents: 0
Enter availability (%): 100
Was system recovered? (1 - yes, 0 - no): 1
```

Очікуваний результат:

```text
Devices: 10
Online devices: 9
Online percentage: 90%
Availability: 100%
Health score: 95
Status: STABLE
Risks:
- 1 devices are offline
```

**Пояснення контрольного прикладу:**

- Загальна кількість пристроїв: 10.
- Кількість пристроїв онлайн: 9.
- Кількість пристроїв офлайн: 10 - 9 = 1.
- Критичних сигналів: 0.
- Перевантажених вузлів: 0.
- Відкритих інцидентів: 0.
- Критичних інцидентів: 0.

Розрахунок:

```text
score = 100 - 1 * 5 - 0 - 0 - 0 - 0
score = 95
```

Оскільки 95 входить до діапазону 80–100, статус платформи — `STABLE`.

Для завершення програми введіть:

```text
Choose: 0
Program finished
```
