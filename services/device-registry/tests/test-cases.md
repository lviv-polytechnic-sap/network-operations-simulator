# Тестові сценарії для сервісу «Реєстр пристроїв» (Team 1)

Відповідно до вимог Розділу 13 ТЗ, нижче наведено оформлені тестові сценарії перевірки C++17 сервісу обліку мережевих пристроїв.

---

### Тест 1: Успішне додавання пристрою
- **ID тесту:** TC-01
- **Категорія:** Позитивний сценарій (Normal Flow)
- **Мета:** Перевірити додавання валідного пристрою та його збереження в реєстрі.
- **Вхідні дані:** ID = 1, Name = "Router-1", Type = "ROUTER", Status = 1 (ONLINE).
- **Очікуваний результат:** Повідомлення про успішне додавання. Пристрій з'являється у загальному списку.
- **Фактичний результат:** Виведено повідомлення `[Успіх] Пристрій успішно додано!`. Запис присутній у таблиці при виводі (опція 4).
- **Статус:** PASS
- **Пов'язаний дефект:** Немає

---

### Тест 2: Заборона дубліката ID
- **ID тесту:** TC-02
- **Категорія:** Спеціальний ризик сервісу (Service Risk)
- **Мета:** Перевірити блокування повторного додавання пристрою з вже існуючим ID.
- **Вхідні дані:** Додавання пристрою з ID = 1, коли ID = 1 вже існує у реєстрі.
- **Очікуваний результат:** Відхилення запису з повідомленням про дублікат ID.
- **Фактичний результат:** Виведено помилку: `[Помилка валідації] Пристрій з ID 1 вже існує (дублікат).`
- **Статус:** PASS
- **Пов'язаний дефект:** Немає

---

### Тест 3: Перевірка некоректного типу пристрою
- **ID тесту:** TC-03
- **Категорія:** Некоректний тип пристрою (Invalid Type)
- **Мета:** Перевірити відхилення типів пристроїв, що не входять до дозволеного списку (ROUTER, SERVER, SENSOR, TERMINAL).
- **Вхідні дані:** ID = 2, Name = "Switch-1", Type = "SWITCH", Status = 1.
- **Очікуваний результат:** Повідомлення про некоректний тип пристрою.
- **Фактичний результат:** Виведено помилку: `[Помилка валідації] Некоректний тип пристрою. Дозволені: ROUTER, SERVER, SENSOR, TERMINAL.`
- **Статус:** PASS
- **Пов'язаний дефект:** Немає

---

### Тест 4: Граничні значення — Пороговий ID та переповнення масиву
- **ID тесту:** TC-04
- **Категорія:** Граничне / Порогове значення (Boundary Value)
- **Мета:** Перевірити валідацію мінімального допустимого додатного ID (1) та поведінку при досягненні ліміту `MAX_DEVICES` (100).
- **Вхідні дані:** Додавання 100-го пристрою (ID = 100) та спроба додати 101-й пристрій (ID = 101).
- **Очікуваний результат:** 100-й пристрій додається успішно. 101-й пристрій відхиляється з повідомленням про заповнений реєстр.
- **Фактичний результат:** 100-й пристрій додано. При 101-му виведено: `[Помилка] Реєстр заповнений (максимум 100 пристроїв).`
- **Статус:** PASS
- **Пов'язаний дефект:** Немає

---

### Тест 5: Некоректний діапазон — Від'ємний ID та нечисловий ввід
- **ID тесту:** TC-05
- **Категорія:** Некоректний діапазон / Захист від помилок вводу (Invalid Input / Range)
- **Мета:** Перевірити відхилення від'ємних ID та стійкість до введення букв у числові поля.
- **Вхідні дані:** Введення ID = -5, а також введення символів "abc" у числове поле ID/Стану.
- **Очікуваний результат:** Від'ємний ID відхиляється. Нечисловий ввід очищається через буфер без аварійного завершення програми.
- **Фактичний результат:** Для ID = -5 виведено: `[Помилка валідації] ID пристрою повинен бути додатним числом (> 0).` При "abc" спрацьовує `clearInputBuffer()` і програма повертає меню.
- **Статус:** PASS
- **Пов'язаний дефект:** Немає

---

### Тест 6: Зміна стану пристрою
- **ID тесту:** TC-06
- **Категорія:** Позитивний сценарій (Modifying State)
- **Мета:** Перевірити зміну стану пристрою з ONLINE (1) на OFFLINE (0) за ID.
- **Вхідні дані:** Зміна стану пристрою ID = 1 з ONLINE (1) на OFFLINE (0).
- **Очікуваний результат:** Стан пристрою успішно оновлюється на OFFLINE.
- **Фактичний результат:** Виведено `[Успіх] Стан пристрою оновлено.`. У таблиці стан змінився на OFFLINE.
- **Статус:** PASS
- **Пов'язаний дефект:** Немає
