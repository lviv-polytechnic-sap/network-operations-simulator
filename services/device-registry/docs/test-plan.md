# План тестування сервісу «Реєстр пристроїв» (Team 1)

## 1. Мета перевірки
Перевірити коректність роботи консольного сервісу `device-registry` (C++17): додавання пристроїв, валідацію полів (`id`, `name`, `type`, `online`), контроль межі масиву (`MAX_DEVICES = 100`), пошук за ID, зміну статусу та виведення таблиці й статистики.

## 2. П'ять тестових сценаріїв

### TC-01: Типовий коректний сценарій додавання пристрою
- **Тип:** Позитивний сценарій.
- **Мета:** Перевірити додавання коректного запису та відображення його у списку й статистиці.
- **Вхідні дані:** Меню `1`, `id = 1`, `name = "Core-Router-1"`, `type = "ROUTER"`, `status = 1` (ONLINE), далі меню `4` (вивести всі пристрої).
- **Очікуваний результат:** Пристрій додано, виведено повідомлення про успіх, запис видно зі статусом `ONLINE`.

### TC-02: Мінімальне допустиме значення ID та статусу
- **Тип:** Мінімальне допустиме значення.
- **Мета:** Перевірити мінімально допустимий додатний ідентифікатор (`id = 1`) та стан `OFFLINE` (`0`).
- **Вхідні дані:** Меню `1`, `id = 1`, `name = "Edge-Sensor"`, `type = "SENSOR"`, `status = 0` (OFFLINE), далі меню `5` (статистика).
- **Очікуваний результат:** Запис прийнято, у статистиці є 1 пристрій `OFFLINE` і 1 `SENSOR`.

### TC-03: Граничне порогове значення ID (`id = 0`) та межа масиву (`MAX_DEVICES = 100`)
- **Тип:** Граничне / порогове значення.
- **Мета:** Перевірити відхилення `id = 0` (оскільки `id > 0`) та контроль верхньої межі масиву (`100` записів).
- **Вхідні дані:** Спроба додати пристрій з `id = 0`; перевірка спроби додати `101`-й пристрій після заповнення `100` записів.
- **Очікуваний результат:** Запис з `id = 0` відхилено; при `100` записах `101`-й пристрій не додається, виходу за межі масиву немає.

### TC-04: Некоректний тип пристрою
- **Тип:** Некоректний тип або діапазон.
- **Мета:** Перевірити відхилення недопустимого типу пристрою без зміни стану реєстру.
- **Вхідні дані:** Меню `1`, `id = 2`, `name = "Switch-1"`, `type = "SWITCH"`, `status = 1`.
- **Очікуваний результат:** Виведено повідомлення про помилку валідації типу, запис не додано, реєстр не змінився.

### TC-05: Спеціальний ризик — дублікат ID та пошук відсутнього пристрою
