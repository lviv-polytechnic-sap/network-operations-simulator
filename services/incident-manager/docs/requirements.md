# Вимоги та критерії приймання сервісу Incident Manager (Команда 5)

## 1. Загальний опис та мета
**Incident Manager** (`services/incident-manager/`) — консольний сервіс на мові C++17 для реєстрації, класифікації, пошуку, ескалації та закриття умовних інцидентів цифрової мережі.

## 2. Модель даних
Основна сутність — структура `Incident`, яка зберігається у статичному масиві фіксованого розміру (`MAX_INCIDENTS = 100`):
- `id` (`int`) — унікальний числовий ідентифікатор інциденту (`id > 0`).
- `source` (`std::string`) — ідентифікатор джерела інциденту (наприклад, `router-1`), непорожній рядок.
- `category` (`std::string`) — категорія інциденту. Допустимі значення: `SIGNAL`, `OVERLOAD`, `DEVICE_OFFLINE`, `DATA_ERROR`.
- `severity` (`std::string`) — рівень критичності. Допустимі значення: `INFO`, `WARNING`, `CRITICAL`.
- `resolved` (`bool`) — стан інциденту (`false` — відкритий, `true` — закритий).

## 3. Функціональні вимоги
- **FR-5.1 (Створення інциденту):** Програма повинна дозволяти користувачеві додати новий інцидент за умови, що кількість записів не перевищує `100`, а всі поля пройшли валідацію.
- **FR-5.2 (Класифікація рівня):** Система підтримує та перевіряє рівні критичності `INFO`, `WARNING` та `CRITICAL`.
- **FR-5.3 (Перегляд відкритих інцидентів):** Програма повинна виводити список усіх активних інцидентів (`resolved == false`). Якщо відкритих інцидентів немає — виводиться відповідне повідомлення.
- **FR-5.4 (Закриття інциденту):** Користувач може закрити відкритий інцидент за його `id` (`resolved = true`). Повторне закриття вже закритого інциденту або закриття неіснуючого `id` заборонене і супроводжується повідомленням про помилку.
- **FR-5.5 (Автоматична ескалація):** Після додавання нового інциденту зі статусом `WARNING` програма підраховує кількість відкритих (`resolved == false`) інцидентів рівня `WARNING` із тим самим `source` (включно з новим). Якщо цей запис став третім (`count == 3`), саме новому інциденту автоматично встановлюється рівень `CRITICAL`. Попередні два записи залишаються без змін, новий додатковий інцидент не створюється. Закриті інциденти (`resolved == true`) при підрахунку не враховуються.

## 4. Нефункціональні вимоги та обмеження
- Мова реалізації: стандарт **C++17**, виключно стандартна бібліотека C++.
- Збірка без попереджень із прапорцями `-std=c++17 -Wall -Wextra -pedantic`.
- Некоректні вхідні дані (нечисловий ID, дублікат ID, порожній `source`, невідома категорія чи рівень) відхиляються без зміни стану масиву.
- Відсутність виходу за межі масиву та глобальних змінних.

## 5. Критерії приймання (Acceptance Criteria)
1. Код успішно компілюється локально через `g++` або `clang++` без помилок та попереджень.
2. Програма поділена щонайменше на 6 змістовних функцій згідно з архітектурою.
3. Контрольний сценарій ескалації (два відкриті `WARNING` для `router-1` + третій `WARNING` для `router-1` → третій отримує `CRITICAL`, перші два лишаються `WARNING`) працює коректно.
4. Закритий `WARNING` не враховується у лічильнику для ескалації наступних записів.
5. Виконано 5 тестових сценаріїв (у тому числі негативні та граничні), результати зафіксовані у `tests/test-cases.md`.
