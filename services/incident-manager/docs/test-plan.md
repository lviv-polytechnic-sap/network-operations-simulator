# План тестування сервісу Incident Manager (Команда 5)

## 1. Мета тестування
Перевірити коректність роботи функціональних вимог (FR-5.1 – FR-5.5), обробку граничних значень, надійність валідації при помилковому введенні користувача та дотримання правил ескалації інцидентів.

## 2. Об'єкт та середовище тестування
- **Вихідний код:** `services/incident-manager/src/main.cpp`
- **Компілятор:** `g++` з прапорцями `-std=c++17 -Wall -Wextra -pedantic`
- **Спосіб тестування:** Чорна скринька (перевірка консольного введення/виведення на наборі підготовлених сценаріїв).

## 3. Обов'язкові категорії тестових сценаріїв
Відповідно до технічного завдання, тестування охоплює 5 ключових категорій:
1. **TC-01 (Типовий коректний сценарій):** Створення звичайного інциденту рівня `INFO` та перевірка його відображення у списку відкритих.
2. **TC-02 (Мінімальне допустиме значення):** Створення інциденту з мінімальним валідним `id = 1` та односимвольним `source = "a"`, а також закриття цього інциденту.
3. **TC-03 (Точне порогове значення — ескалація):** Додавання трьох відкритих інцидентів рівня `WARNING` для одного джерела (`router-1`) для перевірки переходу 3-го інциденту у статус `CRITICAL`.
4. **TC-04 (Некоректний тип або діапазон — негативний тест):** Спроба введення від'ємного ID (`-5`), нечислового ID (`abc`), невідомої категорії (`UNKNOWN`) та неіснуючого рівня (`FATAL`).
5. **TC-05 (Спеціальний ризик сервісу — негативний/логічний тест):** Спроба створити інцидент із повторним `id`, спроба повторно закрити вже закритий інцидент, а також перевірка того, що закритий `WARNING` не впливає на лічильник ескалації.

## 4. Критерії успішності тестування
Тестування вважається успішним, якщо всі 5 сценаріїв мають статус **PASS**, некоректні дані не змінюють стан масиву інцидентів, а фактичні результати повністю збігаються з очікуваними.
