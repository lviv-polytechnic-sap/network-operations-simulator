# Модель даних сервісу incident-manager

## Структура Incident
* **id** (`int`) — унікальний номер інциденту (`> 0`).
* **source** (`std::string`) — назва пристрою/джерела, де стався збій, наприклад `router-1` (непорожній рядок).
* **category** (`std::string` або `enum`) — одна з 4 дозволених категорій: `SIGNAL`, `OVERLOAD`, `DEVICE_OFFLINE`, `DATA_ERROR`.
* **severity** (`Severity`) — рівень критичності: `INFO`, `WARNING`, `CRITICAL`.
* **resolved** (`bool`) — статус вирішення: `false` (відкритий) або `true` (закритий).

## Правила бізнес-логіки (FR-5.1 – FR-5.5)
* **Ескалація:** після додавання нового `WARNING` програма рахує відкриті (`resolved == false`) інциденти рівня `WARNING` для того самого `source`. Якщо новий запис став 3-м, саме йому встановлюється `CRITICAL`. Попередні 2 записи не змінюються.
* **Закриття:** закритий інцидент (`resolved == true`) не враховується при підрахунку попереджень і не закривається повторно.
