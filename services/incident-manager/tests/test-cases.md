# Тестові сценарії сервісу Incident Manager (Команда 5)

| ID | Категорія | Мета | Вхідні дані та послідовність команд | Очікуваний результат | Фактичний результат | Статус | Пов’язаний дефект |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **TC-01** | Типовий коректний сценарій | Перевірити успішне створення та виведення відкритого інциденту рівня `INFO` | 1. Обрати пункт додавання інциденту<br>2. Ввести: `id = 10`, `source = "switch-1"`, `category = "SIGNAL"`, `severity = "INFO"`<br>3. Обрати перегляд відкритих інцидентів | Інцидент `ID: 10` додано зі статусом `INFO` (`resolved = false`) та відображено у списку відкритих інцидентів | Інцидент успішно створено і виведено у списку активних записів з коректними полями | PASS | — |
| **TC-02** | Мінімальне допустиме значення | Перевірити роботу на нижній межі валідності (`id = 1`, `source = "a"`) та закриття інциденту | 1. Додати інцидент: `id = 1`, `source = "a"`, `category = "DATA_ERROR"`, `severity = "WARNING"`<br>2. Обрати закриття інциденту за `id = 1`<br>3. Переглянути список відкритих | Інцидент створюється без помилок, після закриття отримує `resolved = true` і зникає зі списку відкритих інцидентів | Інцидент з `id = 1` створено, після команди закриття статус змінено, список відкритих порожній | PASS | — |
| **TC-03** | Точне порогове значення (ескалація) | Перевірити правило ескалації 3-го відкритого `WARNING` для одного джерела (`router-1`) | 1. Додати: `id = 1`, `source = "router-1"`, `category = "OVERLOAD"`, `severity = "WARNING"`<br>2. Додати: `id = 2`, `source = "router-1"`, `category = "SIGNAL"`, `severity = "WARNING"`<br>3. Додати: `id = 3`, `source = "router-1"`, `category = "DEVICE_OFFLINE"`, `severity = "WARNING"`<br>4. Переглянути відкриті інциденти | Перші два інциденти (`id = 1`, `id = 2`) залишаються `WARNING`. Третій інцидент (`id = 3`) автоматично отримує рівень `CRITICAL` | Записи `id = 1` та `id = 2` мають рівень `WARNING`, запис `id = 3` автоматично отримав рівень `CRITICAL` | PASS | — |
| **TC-04** | Некоректний тип або діапазон (негативний) | Перевірити захист від нечислового ID, від'ємного ID та неіснуючої категорії | 1. Спробувати додати інцидент з `id = -5`<br>2. Спробувати додати інцидент з `id = "abc"`<br>3. Спробувати додати інцидент: `id = 5`, `source = "srv-1"`, `category = "HACK"`, `severity = "INFO"`<br>4. Переглянути відкриті інциденти | Програма виводить повідомлення про помилку валідації/введення на кожній спробі, не аварійно завершується, стан масиву не змінюється (0 записів) | Усі 3 спроби відхилені з відповідними повідомленнями про помилку, масив залишився порожнім | PASS | — |
| **TC-05** | Спеціальний ризик сервісу (дублікат ID та закриті інциденти) | Перевірити блокування дубліката ID, повторного закриття та неврахування закритого `WARNING` при ескалації | 1. Додати `WARNING` для `node-1` (`id = 1`) і одразу закрити його (`id = 1`)<br>2. Спробувати ще раз закрити `id = 1`<br>3. Додати ще два відкриті `WARNING` для `node-1` (`id = 2` та `id = 3`)<br>4. Спробувати додати інцидент із повторним `id = 2` | Повторне закриття `id = 1` відхилено; інцидент `id = 3` залишається `WARNING` (бо відкритих лише 2); дублікат `id = 2` відхилено | Повторне закриття заблоковано, `id = 3` залишився у статусі `WARNING`, дублікат `id = 2` не додано | PASS | — |
